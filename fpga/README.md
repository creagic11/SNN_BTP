# FPGA implementation and power-estimation flow

Device: Xilinx Artix-7 XC7A100T-1CSG324C (the device of the Digilent Nexys A7-100T board). Tool: Vivado 2024.1 in
non-project mode, default synthesis and implementation directives unless stated. Clock: 100 MHz.

## Flow

Each run is started from the Vivado 2024.1 Tcl Shell on Windows. Paths inside the scripts are relative to the
repository, so the commands below work from any checkout location:

```
cd <repository>/fpga
exec -ignorestderr cmd /c run_l1.bat
exec -ignorestderr cmd /c run_l2.bat
```

A run has three steps:

1. **Build** (`prep_l1.tcl`, `prep_l2.tcl`, Vivado batch). Synthesis, placement and routing of each design; reports
   of utilisation (`util.rpt`, `util_hier.rpt`, `ram_util.rpt`), timing (`timing.rpt`) and vectorless power. For
   each power build, the routed functional netlist is written (`write_verilog -mode funcsim`) and compiled for
   simulation with the Xilinx simulation libraries.
2. **Gate-level simulation** (the `:sim` step of the batch file). The routed netlist is simulated in xsim over 20
   back-to-back test inferences, and the switching activity of every net is written to a SAIF file. xsim is run as
   a separate process because launching it from inside Vivado failed with an access violation on the build machine.
3. **Power** (`annotate_l1.tcl`, `annotate_l2.tcl`, fresh Vivado). `fix_saif_names.tcl` rewrites xsim's escaped net
   names into the form that `read_saif` matches; `read_saif` and `report_power` then give the activity-based power.
   Energy per inference is total power multiplied by the mean latency measured in the gate-level simulation.

Results are written to `../out_l1/` and `../out_l2/` (not tracked) and copied to `results/power_l1/` and
`results/power_l2/`.

## Designs

| Top level | Configuration | Used for |
| --- | --- | --- |
| `top_net.sv`, `STREAM = 0` | Whole network (`rtl/hush_net.sv`); the events of 20 test recordings are stored on chip and processed back to back | Power, energy, latency, area (Table IV of the paper) |
| `top_net.sv`, `STREAM = 1` | Whole network with the sensor front-end and a 1,024-event ring; a pseudo-random event generator drives the sensor port | Area and timing of the real-time configuration |
| `spikerplus/fpga/top_spiker.vhd` | Spiker+ 578-256-10 network with the same 20 recordings | Same-device baseline |
| `top_hush.sv` | Hidden layer only (earlier flow, `prep_v5.tcl`, `run_v5.bat`) | Archived results in `results/archive/power_saif_v5/` |

Every output of every design is folded into the board LEDs, so that synthesis cannot remove logic whose result is
not observed. All tables are writable block RAMs loaded through a UART port (`uart_loader.sv`), so that synthesis
cannot specialise the logic to constant weights. `nexys_a7_100t.xdc` holds the pin and clock constraints.

Memory images are generated by `scripts/make_net_hex.py --nsmp 20` into `netpwr/<case>/` and `netstream/<case>/`.
Each folder also holds `expected.csv` with the predicted class and model cycle count of every recording.

## Acceptance checks

A run is accepted only if:

- every build meets timing (WNS ≥ 0);
- `util_hier.rpt` shows all 32 lanes and all four weight-column memories in both layers, so no logic was removed;
- `read_saif` matches at least 99.9 % of nets with confidence "High";
- every simulated inference takes the cycle-model count plus the fixed restart overhead (3 cycles; 7 for the
  first inference after reset).

## Design history

The following corrections were made on 28 October 2026 after an audit of the first builds. Each was verified
bit-exact in simulation.

| Change | Reason |
| --- | --- |
| LEDs fold all 32 spikes and all 512 state bits | The first top level observed only lanes 0–5 and 26–31, so synthesis removed most of BASE |
| Every table is a writable block RAM with a UART load port | As ROMs, synthesis trimmed the INT8 weights to 6 bits |
| Four 64-bit weight-column memories, each read only when its sub-block is awake | Column gating had been modelled only in a counter |
| Window boundaries stored as {ts[t+1], ts[t]} pairs in a true-dual-port block RAM | Four read ports had been implemented as a 10k-LUT ROM in HUSH only |
| `ram_decomp = "power"` on the deep event and weight memories | Each read enables one block RAM (in both BASE and HUSH) |
| Event index registered before the weight address | Critical path (−2.26 ns) |
| Named generate scopes in the max tree | Unnamed scopes produced net names that `read_saif` rejects |

Timing closure of the hidden layer:

| Build | Change | HUSH WNS |
| --- | --- | --- |
| 27 Oct, 1 | Original RTL | −14.8 ns |
| 27 Oct, 2 | Two-stage finalise | −4.0 ns |
| 27 Oct, 3 | Balanced two-stage max tree for R | +0.45 ns |
| 28 Oct, v5 | Writable memories, column enables, event-index register | +0.496 ns |
